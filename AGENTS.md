# Инструкции для агентов: CYBERCORE

Этот файл задаёт постоянные правила работы в репозитории. Для требований к сайту обращайтесь к `TECHNICAL_SPEC.md`, для согласованной архитектуры, этапов и условий запуска — к `PLAN.md`. Читайте нужные разделы по задаче; не дублируйте эти документы здесь. Новые указания пользователя имеют приоритет над прежними решениями в документах.

## Границы проекта

- CYBERCORE — русскоязычный коммерческий лендинг компьютерного клуба. Публичный интерфейс должен выглядеть как законченный продукт; не добавляйте в страницы, metadata и сообщения слова «демо», «портфолио», «учебный проект» и похожие.
- MVP: один проект Next.js App Router, React и TypeScript; заявка через `POST /api/booking` и настроенный почтовый сервис. Не добавляйте Prisma, базу данных, CMS, личный кабинет или отдельный backend без новой задачи.
- Держите контакты, режим работы, тарифы, зоны, FAQ и турниры отдельно от компонентов в типизированных файлах данных. Предпочитайте простые компоненты и минимальное число зависимостей.
- Для кириллических заголовков и текста используйте Inter; Space Grotesk — для латинского логотипа, латинских названий и чисел. Следуйте палитре и адаптивным требованиям ТЗ.

## Контент и публикация

- На этапе закрытой предварительной версии допустимы согласованные с заказчиком правдоподобные вымышленные данные и изображения. Помечайте их черновыми внутри конфигурации и документации, чтобы их можно было заменить без правки компонентов. Не используйте случайные действующие контакты третьих лиц.
- Перед публичным запуском проверьте и замените черновые контакты, адрес, часы, цены, оснащение, изображения, юридические сведения и события. Не публикуйте вымышленные отзывы, рейтинги или `LocalBusiness` с неподтверждённым адресом. Карту показывайте только по подтверждённому адресу; регистрацию на турнир — только с рабочей ссылкой или обработчиком.
- Отправленная заявка не означает автоматического резерва места. Не показывайте успешную отправку, пока почтовый сервис не подтвердил приём письма; при отсутствии настройки или ошибке возвращайте понятную ошибку.
- Vercel Hobby рассматривается для предварительной проверки в допустимых пределах. Публичный коммерческий запуск требует отдельного решения по подходящему тарифу или хостингу; не выполняйте его как обычный шаг реализации.

## Код, безопасность и проверка

- Основной контент оставляйте в Server Components; клиентский код добавляйте для конкретных взаимодействий. Не передавайте почтовые секреты в браузер и не используйте `NEXT_PUBLIC_` для секретов.
- Проверяйте входные данные формы и на клиенте, и на сервере. Не храните и не логируйте персональные данные в приложении; предусмотрите согласие, утверждённую политику, ограничения запросов и защиту от спама перед приёмом реальных заявок.
- Поддерживайте клавиатурную навигацию, видимый фокус, `prefers-reduced-motion`, адаптивность от 320 до 1920 px, SEO и загрузку изображений без заметного сдвига макета.
- После изменений запускайте относящиеся к ним команды из `package.json`. Перед завершением существенной реализации проверьте `lint`, `typecheck`, тесты и production build. Для интерфейсных изменений проверяйте отрендеренный результат, а не только сборку.

## Skills

Используйте инструкции релевантных skills из `.agents/skills/` в соответствующей работе, без обязательной загрузки всех skills для каждой мелкой правки:

- `frontend-design` — при создании или существенном изменении визуального интерфейса.
- `vercel-react-best-practices` — при написании и изменении React/Next.js-кода, особенно клиентских границ и производительности.
- `frontend-testing-debugging` — при проверке отрендеренного интерфейса, адаптивности и взаимодействий.
- `security-best-practices` — при работе с формой, API, персональными данными, секретами и проверками безопасности.

`prisma-orm-setup` в MVP не применять. Если инструкция skill расходится с текущим указанием пользователя или требованиями проекта, следуйте указанию пользователя и объясните значимое расхождение.
