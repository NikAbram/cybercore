# Техническое задание: CYBERCORE — Gaming Club

**Версия:** 1.1  
**Тип:** коммерческий лендинг компьютерного клуба  
**Язык:** русский  
**Цель:** представить клуб, его игровые зоны и тарифы, обеспечить удобную отправку заявок.

## 1. Описание проекта

Создать современный одностраничный сайт премиального компьютерного клуба **CYBERCORE**. Сайт должен выглядеть и работать как готовый коммерческий продукт: качественный дизайн, адаптивная вёрстка, доступность, анимации, интерактивные компоненты, формы и серверная валидация.

Целевая аудитория: геймеры 16–35 лет, любители киберспорта и компании друзей.

Контакты, адрес, цены и даты событий должны задаваться в отдельных конфигурационных файлах. Перед публикацией заменить все примерные значения на проверенные данные. Не придумывать действующие адреса, телефоны, мероприятия или отзывы.

## 2. Стек

- Next.js (App Router), React, TypeScript.
- Tailwind CSS.
- Motion / Framer Motion для уместных анимаций.
- Lucide React для иконок.
- React Hook Form + Zod для форм.
- Next.js Route Handlers для API обработки заявок.
- ESLint, Prettier.
- Vitest + Testing Library; Playwright для E2E.
- Деплой на Vercel.

**Не подключать Prisma и базу данных в MVP.**

## 3. Дизайн

Стиль: технологичный, минималистичный, премиальный gaming / esports. Тёмный интерфейс, красные акценты, атмосферные фотографии клуба, выразительная типографика. Не перегружать интерфейс неоном и анимациями.

## 4. Структура страницы

### 4.1. Header
- Логотип CYBERCORE.
- Навигация по якорям: преимущества, зоны, тарифы, турниры, галерея, контакты.
- Кнопка «Забронировать».
- Sticky header и мобильное меню.

### 4.2. Hero
- Заголовок «ТВОЯ ИГРА. ТВОИ ПРАВИЛА.».
- Краткий подзаголовок о клубе.
- Атмосферное фоновое изображение с затемнением для читаемости.
- CTA «Забронировать ПК» и «Смотреть тарифы».

### 4.3. Преимущества
Четыре карточки: мощные игровые ПК, мониторы 240 Гц, профессиональная периферия, комфортные игровые зоны. Каждая — с иконкой и коротким описанием.

### 4.4. Игровые зоны
Три категории: Standard, VIP, Bootcamp. Для каждой показать изображение, характеристики оборудования, вместимость, преимущества, стоимость и кнопку бронирования.

### 4.5. Тарифы
- Переключение «Почасовые / Пакеты» без перезагрузки.
- Карточки с названием, ценой, продолжительностью и особенностями.
- Визуальное выделение популярного тарифа.
- Кнопки «Забронировать».
- Цены хранить в отдельном файле данных.

### 4.6. Турниры
Карточки событий по CS2, Dota 2, Valorant: название, дата, дисциплина, призовой фонд, статус. Публиковать только актуальные и подтверждённые события из конфигурации. Если событий нет, показывать аккуратное состояние «Скоро новые турниры» без выдуманных дат и призовых фондов. Кнопку регистрации выводить только при наличии работающей ссылки или обработчика.

### 4.7. Галерея
- Адаптивная сетка изображений клуба.
- Lightbox с полноэкранным просмотром.
- Переключение стрелками, закрытие Escape, управление клавиатурой.
- Alt-тексты и оптимизация изображений.

### 4.8. Контакты и FAQ
- Адрес, режим работы, телефон и социальные сети из конфигурации. Показывать только проверенные и заполненные данные.
- Карта по подтверждённому адресу; при отсутствии адреса скрывать карту и не подставлять случайную локацию.
- FAQ-аккордеон с 5–7 вопросами.
- Footer с навигацией, контактами и юридической информацией при наличии.

## 5. Функциональность

### 5.1. Навигация
- Плавная прокрутка к секциям с учётом высоты sticky header.
- Активный пункт меню.
- Доступное мобильное меню с управлением клавиатурой.
- Не должно быть неработающих кнопок или ссылок `#` без действия.

### 5.2. Форма заявки на бронирование
По нажатию CTA открывается доступное модальное окно с полями:

1. Имя.
2. Телефон в российском формате.
3. Игровая зона.
4. Дата посещения (не в прошлом).
5. Время начала.
6. Продолжительность сеанса.
7. Количество мест (1–5).

Требования:
- React Hook Form + Zod; клиентская и серверная валидация.
- Route Handler `POST /api/booking` принимает и валидирует заявку.
- Реализовать отправку заявки через серверный обработчик на настраиваемый email администратора (почтовый провайдер через переменные окружения). Секреты хранить только на сервере.
- Не имитировать успешную отправку: при отсутствии конфигурации почтового провайдера или ошибке доставки возвращать понятную ошибку.
- После подтверждённой отправки показывать: «Заявка отправлена. Мы свяжемся с вами для подтверждения бронирования».
- Отправка заявки не означает автоматического резервирования места. Не показывать статус «Бронирование подтверждено» без реальной системы учёта свободных мест.
- Не хранить персональные данные в базе данных; передавать их только настроенному провайдеру доставки письма. Добавить согласие на обработку данных и ссылку на политику конфиденциальности, если форма собирает персональные данные.
- Состояния loading, success, error; предотвращение повторной отправки.
- Корректное управление фокусом, Escape и блокировка фоновой прокрутки в модальном окне.
- Не логировать персональные данные. Добавить базовую защиту от спама и ограничение частоты запросов, не раскрывать серверные ошибки клиенту.

### 5.3. Дополнительная интерактивность
- Переключатель тарифов.
- FAQ-аккордеон.
- Галерея с lightbox.
- Toast-уведомления.
- Анимации появления секций с поддержкой `prefers-reduced-motion`.

## 6. Адаптивность

Проверить ширины 320, 375, 768, 1024, 1440 и 1920 px. Не допускать горизонтального скролла. На мобильных устройствах — одноколоночные карточки, удобные касания, компактная навигация и модальные окна внутри viewport.

## 7. SEO, доступность и производительность

- Семантическая HTML-структура, один `h1`, логичная иерархия заголовков.
- `title`, `description`, Open Graph, favicon, sitemap, robots.txt.
- `next/image`, адаптивные изображения, lazy loading ниже первого экрана.
- Контраст текста, видимые focus states, подписи полей, aria-атрибуты там, где необходимы.
- Поддержка клавиатуры и `prefers-reduced-motion`.
- Отсутствие критических ошибок в консоли и layout shift.
- Целевые оценки Lighthouse в production: Performance 90+, Accessibility 95+, Best Practices 95+, SEO 95+. Это цели, а не гарантированные результаты.

## 12. Контент и публичное позиционирование

- На публичных страницах, в metadata, Open Graph, структурированных данных, footer и сообщениях интерфейса **не использовать** формулировки «демо», «демонстрационный проект», «портфолио», «учебный проект» и подобные.
- SEO-тексты должны описывать услуги компьютерного клуба естественно, без переспама ключевыми словами.
- Не создавать ложные сведения о реальном бизнесе: до публикации проверить контакты, адрес, цены, расписание, юридические сведения и доступность бронирования.
- Для сайта без подтверждённых бизнес-данных не добавлять вымышленные отзывы, рейтинги или разметку LocalBusiness с несуществующим адресом.
- Техническая документация может описывать ограничения функциональности, но эти формулировки не должны попадать в публичный интерфейс.
